## Supplementary materials for reviewers

- Existing formal report submission now offers a collapsed optional written note and PDF/PNG/JPEG/WebP selection. Up to **3 files**, **4 MB each**, note **4000 characters**. Editable/removable before explicit Submit; disabled during file reading/submission; failure retains the draft for explicit retry. No materials never blocks existing Submit.
- Server verifies owner, session, standardized certification identity, entitlement and existing persisted evaluation. It validates size/count, filename/type/signatures and PDF completeness; rejects detectable scripts, embedded files and encrypted PDFs. This is bounded signature validation, **not antivirus or comprehensive PDF sanitization**. No AI document interpretation or embedded-command execution.
- Staged `reviewer_supplements` stores immutable submitted note/file metadata separately from evaluations. Service-only row-locked RPC rechecks owner/evaluation, atomically freezes material metadata with submission and rejects changed retry payloads and historical submissions. No backfill or score updates.
- Reuses the existing **private** `playbooks` bucket with reserved `reviewer-supplements/<owner>/<session>/<request>/<content hash>` paths. No public or signed URLs. Existing user-folder policies cannot directly access this prefix; staged restrictive storage policy prevents future permissive-policy bypass. Raw file downloads pass through the authenticated handler, checking current owner or authorized reviewer/admin of a submitted standardized session before privileged reading. Files return only to that caller as bytes for a local browser download. No arbitrary reviewer recipient input.
- Only the owner and currently authorized human reviewer/admin can read submitted material metadata. Custom practice is excluded. Unsubmitted material drafts stay browser memory, never uploaded; raw bytes are saved only during explicit formal submit. Uploads succeeded before a later RPC failure may leave private orphan files; identical retry reuses content-addressed keys without overwrites. An approved isolated retention/cleanup policy is a deployment prerequisite, not silently installed here.
- Historical assessments and submissions show no new material record. Existing AI scoring and human decisions are untouched. Reviewer Inputs labels materials as separate from original AI scoring.
