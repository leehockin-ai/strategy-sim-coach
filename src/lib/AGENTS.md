# Normal facilitation reference
- Reviewer supplements freeze separately at explicit formal submission, never feed AI scoring; reserved private object paths are downloaded only after owner/session or submitted-session reviewer authorization, and absent staged capability fails closed without blocking empty submission.
- Historical playbook dialogue stays visible with original source IDs but does not reindex normal board notes; saved Scope decisions ignore stale external conclusions while already-advanced/legacy evidence exemptions remain unchanged.
- All committed Chapter 2 approaches use one shared conversation selector, including historical methodology-only sessions; alternative planning is supplementary and prior canvas evidence is read-only to prevent partial feature sets and duplicate rooms.
- Formative compatibility guidance requires explicit practice identity in UI and server responses; unmarked historical sessions default to certification, while private scenario identity excludes title-matched curated starter facts and hydrates all prompt context.
- Client-team interaction uses shared semantic prompt rules and actual transcript continuity, never profanity/sentiment scoring; explicit participant refusals remain speech but cannot source new work or disclosures, while other speakers retain independent agency.
- Assessment notices use the registered template and deployment-allowlisted report links behind disabled completion gates; managed delivery deduplicates by assessment, while optional Gmail requires a durable pre-POST reservation and holds unknown outcomes because Gmail has no idempotency. Staged claim/settle remains unapplied, report reads never backfill, and no generic send endpoint or platform queue is introduced.
- Custom intake stays transient until Start; an owner-RLS idempotent RPC freezes the approved draft on ordinary sessions, and all scenario consumers hydrate that snapshot rather than inserting private catalog rows; absent capability fails closed.
- Workspace content scroll is presentation-only and bounded independently of its heading/tabs/revision selector; only new note IDs while following latest reveal their actual DOM note, never grid-bottom scrolling, view changes, revision edits or historical snapshots.
- Chapter 2 transcript scroll is presentation-only: initial/session open, near-bottom new turns and successful coach sends follow latest; source navigation focuses and scrolls within the labelled native pane without moving the composer or altering stored messages.
- Chapter 2 visual workspace adapters reuse the same notes and revisions; source origins follow ordered validated reference switches, starters retain Scope origin, legacy rows fall back to unknown, and assumption placement requires both explicitly stated axes rather than inferred certainty.
- Screenshot references in Chapter 2 are validated inline PNG/JPEG/WebP, streamed through the existing owner-authorized team handler and never stored; only a notice and attributed team speech persist, preventing a public/private attachment store or image-derived evidence claim.
- Chapter 2 dictation/read-aloud reuses existing browser and stakeholder voice paths with opt-in, editable text and no automatic submission; typed, spoken and screenshot questions share one conversation.
- Normal Chapter 2 board = deterministic view-only starter notes (exact sentences of a visible, attributed, scenario-grounded opening; layout from verified metadata or the coach-saved title/brief, never inferred playbook contents) plus projections of roster-attributed persisted team messages: explicit <<add KEY>>/<<revise ID>> markers in team speech (validated server-side, stripped from display) and conservative regex/correction reconciliation; starter notes are never assessment evidence and no new storage is used.
- Playbook choice lives in the versioned Engagement Brief (`playbook_selection`) and Chapter 2 only reads it; validated canonical Library listings and project playbook runs retain distinct kinds and IDs with labelled provenance, so Scope revisions freeze the decision without schema changes or a duplicated catalog. Project run references never infer listing metadata or load private content.
- The Scope playbook choice is never held only on screen: valid edits enter the Engagement Brief's single serialized autosave and incomplete choices block leaving Scope; Your Approach summarises saved Scope and submits into Chapter 2, which shows that exact saved choice and renders exactly one surface: any saved Scope decision (playbook, none, defer) uses the in-app session regardless of stale external runs or allowlist; the external test room appears only for allowlisted sessions with no Scope decision.
- Chapter 2 playbook switches are coach-authored message rows in phase playbook:switch:v1 (validated JSON, owner-checked, stale-state guarded); Scope is never rewritten, starter notes stay Scope-derived, and turns carry the expected active reference so none is ambiguously attributed.
- Live Client Team (external Strategyzer runs): one shared room per run; team/system events and private annotations are written only through the server-only append_team_events function after an owner check; participants/evidence live in server-only team_activity_configs, POC configs run only in allowlisted test sessions, and evidence counts as surfaced only when its holder speaks. Never recreate the Strategyzer artifact.
- Causal team-work turns use the service-only append_team_work_turn wrapper to atomically persist ordered responses, private state and event-linked work revisions with stable request identity and optimistic sequence/revision checks; external artifacts are team-owned, never candidate-editable.
- Assessment generation is a resumable job in the server-only evaluation_jobs table: owner-checked start/advance/status functions run one bounded batch per request under an atomic lease, so no single request carries the whole generation and progress survives refreshes; existing evaluations are never overwritten.
- Live-room conclusions carry a public conclusion_mode (early_stop from the working phase, after_synthesis otherwise); early stop never writes a synthesis event, and unmarked historical conclusions read as unspecified, so the record never claims a step the coach did not take.
